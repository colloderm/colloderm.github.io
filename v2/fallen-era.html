FallenEra

직접 해 보기

FallenEra의 배치 규칙과 지지 계산 원리를 브라우저로 옮긴 단순화 데모입니다. 토대 400cm, 스냅 반경 150cm, 붕괴 간격 0.1초는 게임과 같습니다. 실제 게임은 피스마다 지지 비용이 다른 다익스트라로 계산하지만, 데모는 모든 비용을 1로 둔 BFS입니다.

소켓 스냅 배치

위에서 내려다본 토대입니다. 가장자리 소켓 가까이로 커서를 옮기면 고스트가 붙고, 이미 있는 자리면 빨간색으로 거부됩니다. 클릭하면 같은 검증 함수로 한 번 더 확인한 뒤 놓습니다.

대표 문제 해결: 받침을 잃은 계단이 떠 있던 문제

문제

2층 천장에 매단 계단이 마지막 받침을 잃어도 무너지지 않고 공중에 떠 있었습니다.

원인

"연결된 피스가 하나도 없으면 땅에 닿은 것"으로 판정하고 있어서, 받침을 모두 잃는 순간 오히려 땅에 닿은 피스로 바뀌었습니다.

수정

바닥면이 실제 지형과 겹칠 때만 땅에 닿은 것으로 판정하도록 바꾸고, 배치 예측, 완성 판정, 지지 재계산이 같은 판정 함수 하나를 쓰게 했습니다.

이어진 수정

다음 리뷰에서 토대(20cm) 위 함정이 토대 아래 땅에 닿은 것으로 잡히는 문제가 나와, 가구와 방어시설의 허용 오차를 25cm에서 5cm로 줄였습니다. 판정 결과는 저장하지 않고 매번 검사해서 저장 데이터와 복제 값은 늘지 않았습니다.

전체 구조

모든 건설물은 AFEBuildPiece 하나를 부모로 두고, 메시, 비용, 소켓, 내구도는 데이터 에셋에 있습니다. 팀원 시스템과는 인터페이스 두 개로만 연결됩니다.

UFEBuildingComponent

캐릭터에 붙는 건설 담당 컴포넌트입니다.

  • 빌드 모드 전환, 고스트 미리보기, 배치 검증
  • 배치, 철거, 수리, 업그레이드 서버 RPC
  • HUD를 직접 참조하지 않고 델리게이트로 상태만 알림

UFEBuildHudComponent

건설 UI와 패널 RPC를 맡습니다. 코드 리뷰 후 건설 컴포넌트에서 분리했습니다.

  • MVVM 뷰모델과 빌드 메뉴(건설, 가구, 방어 탭)
  • 재료 투입, 보관함, 화로, 탄약 패널
  • 의존 방향은 HUD에서 건설 쪽 한 방향뿐

UFEBuildingSubsystem

월드 단위로 모든 피스를 관리합니다.

  • 지지 거리 재계산과 붕괴 큐
  • 피스 레코드 저장과 복원
  • 건설 에셋 미리 로드

UFEBuildPieceDefinition

피스 하나를 정의하는 UPrimaryDataAsset입니다.

  • 메시, 필요 재료, 최대 체력, 소켓 목록
  • 업그레이드 대상 (나무에서 돌, 돌에서 철)
  • 에셋은 소프트 참조, Asset Manager로 비동기 로드

지지 거리 재계산

데모의 계산과 같은 부분입니다. 땅에 닿은 피스에서 출발하는 정수 비용 다익스트라입니다.

FEBuildingSubsystem.cpp지지 거리 재계산 (일부)
// 정수 비용 다익스트라. anchor(땅에 닿은 피스)가 출발점.
while (Frontier.Num() > 0)
{
    // 프론티어에서 거리가 가장 짧은 피스를 꺼낸다
    AFEBuildPiece* Current = Frontier[BestIndex];
    Frontier.RemoveAtSwap(BestIndex);
    const uint8 CurrentDistance = OutDistance[Current];

    // 가구 · 방어시설은 다른 피스를 받치지 않는다
    if (!CanSupportOthers(Current)) continue;

    for (AFEBuildPiece* Neighbor : Adjacency[Current])
    {
        uint8* NeighborDistance = OutDistance.Find(Neighbor);
        if (NeighborDistance == nullptr) continue;

        const int32 Candidate = FMath::Min<int32>(CurrentDistance + Neighbor->GetSupportCost(), Unreachable);
        if (Candidate < *NeighborDistance)
        {
            *NeighborDistance = static_cast<uint8>(Candidate);
            Frontier.AddUnique(Neighbor);
        }
    }
}

요청 간격 제한

수리, 업그레이드, 발사, 조준 요청이 함께 쓰는 함수입니다. 지터로 조금 일찍 온 요청은 받되 평균 간격은 지키고, 자동화 테스트로 검증합니다.

FEBuildingTypes.h요청 간격 제한 (수리 · 업그레이드 · 발사 · 조준 공용)
inline bool ConsumeRequestSlot(double& NextAllowedTime, double Now, double Interval)
{
    if (Now < NextAllowedTime - Interval * 0.5) return false;
    NextAllowedTime = FMath::Max(NextAllowedTime, Now) + Interval;
    return true;
}

청사진, 재질, 수리

청사진과 재료 투입

  • 배치하면 먼저 반투명 청사진이 생기고, E로 재료를 넣어야 완성됩니다.
  • 처음 넣은 재료로 재질이 정해집니다. 나무를 넣으면 나무 벽, 돌을 넣으면 돌 벽이 됩니다.
  • 청사진을 철거하면 넣은 재료를 모두 돌려받습니다.

망치로 수리와 업그레이드

  • 망치를 들고 좌클릭하면 수리, 우클릭하면 다음 재질로 업그레이드합니다.
  • 업그레이드는 같은 액터에서 정의 데이터만 바꿔 위치, 소켓, 문 열림 상태가 유지됩니다.
  • 수리 비용은 깎인 체력 비율 × 재료 × 0.5입니다.
재질최대 체력필요 재료업그레이드
나무300나무돌로
돌800돌철로
철1,500철괴마지막 단계

가구, 함정, 탑승형 발리스타

  • 스파이크와 철조망은 자체 AbilitySystemComponent와 AttackPower를 가지고, 전투 담당 팀원의 GAS 피해 경로를 그대로 써서 피해를 줍니다. 피해는 서버만 계산하므로 함정의 ASC는 복제하지 않습니다.
  • 발리스타에 E로 탑승하면 서버가 Owner를 탑승자로 바꿔, 그 플레이어만 발사와 조준 RPC를 보낼 수 있습니다.
  • 조준은 내 화면에 즉시 반영하고, 다른 플레이어에게는 int8 각도로 초당 10회 이하만 보냅니다. 패킷을 잃어도 0.5초마다 다시 보내 맞춰집니다.
  • 발사는 서버가 탄약, 장전 시간, 볼트 로드 여부를 확인한 뒤 오브젝트 풀에서 투사체를 꺼내 쏩니다.
FEBuildBallista.h
/** [Server RPC] 발사. 조준은 정밀값(float, 발리스타 기준 상대 각도) — 리플리케이트용 int8 은 1° 단위라 멀리서 빗나간다 */
UFUNCTION(Server, Reliable, WithValidation)
void ServerFire(float Yaw, float Pitch);

/** [Server RPC] 조준(상대 각도, 도). 다른 플레이어에게 보이는 용도라 Unreliable, 바뀌면 10Hz 이하 + 그대로여도 0.5초마다 재전송 */
UFUNCTION(Server, Unreliable, WithValidation)
void ServerSetAim(int8 Yaw, int8 Pitch);

/** [Client RPC] 서버만 아는 발사 실패 사유를 조작자 화면에. Owner = 조작자라 그 플레이어에게만 간다 */
UFUNCTION(Client, Reliable)
void ClientShowNotice(const FText& Text);

인터페이스 하나로 다섯 가지 상호작용

문 열기, 재료 투입, 보관함 열기, 발리스타 탑승, 아이템 줍기가 모두 IFEInteractable 하나로 동작합니다.

FEInteractable.h
class IFEInteractable
{
    /** 클라/서버 공용. 대상 필터와 프롬프트 표시 */
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable)
    bool CanInteract(AActor* InstigatorActor) const;

    /** 프롬프트 문구. 예: "문 열기" */
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable)
    FText GetInteractText(AActor* InstigatorActor) const;

    /** [Server Only] 거리와 CanInteract 재검증 후 호출 */
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable)
    void Interact(AActor* InstigatorActor);

    /** [Client Only] 서버 성공 후 UI 열기 · 로컬 연출 */
    UFUNCTION(BlueprintNativeEvent, BlueprintCallable)
    void InteractLocal(AActor* InstigatorActor);
};
  1. 대상 찾기클라이언트가 조준한 액터의 CanInteract와 안내 문구를 표시
  2. 서버 재검증상호작용 컴포넌트가 거리와 CanInteract를 다시 확인
  3. Interact서버에서 문 열림, 재료 투입 같은 상태 변경
  4. InteractLocal패널 열기처럼 요청한 플레이어 화면에서만 처리
